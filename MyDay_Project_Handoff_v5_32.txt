【1. 本次目的與工作邊界】
這是保守式程式碼安全／品質審視，不是大規模改版：
- 保留原有 21 個 Widget、卡片順序、大小、標題、資料來源、日期提醒、圖片剪裁、Hover、分頁、香港時間及 UI 操作。
- 不改任何原有 HTML Widget 結構，也不修改整份 CSS；無原有資料鍵的搬遷、刪除或改名。
- 現有資料仍儲存於使用者自己的瀏覽器；不會上傳私人的提醒、重要日子及圖片到 GitHub。
- 不使用真實帳戶、真實資料或遠端網絡做自動驗收；測試使用 Chromium、本地合成資料和禁止外部 HTTP 的環境。

【2. 本次實際改動（v5.31 → v5.32）】
A. Javascript：兩個時間顯示格式器改為重用同一個 Intl.DateTimeFormat 實例，輸出格式／時區設定不變，減少更新時重複配置。
B. 本機資料防呆：提醒及重要日子從 localStorage 載入時，只接受陣列及陣列內的普通資料物件；對不合理結構採用安全的顯示回退。不改寫已儲存的有效資料。
C. HTML 內容模板：把「我的提醒」、「重要日子」的空白提示共用 emptyListCue()，仍沿用原來的 HTML 結構、提示字句及 CSS。
D. 前端新聞連結防護：由單純 https:// 前綴檢查，加強至只接受 RTHK 真正的 HTTPS 主機名稱（rthk.hk 或其子網域）、拒絕帳戶密碼／偽裝主機／非預期埠。
E. scripts/fetch_news.py：抓取新 RSS 及讀取離線快取時，均驗證同一份官方 RTHK 網域規則；快取資料須具有效結構；超過 1.5 MB 的 RSS 明確拒絕而非靜默截斷。
F. 廢碼清理：移除完全沒有呼叫的舊版自製恒指 drawMarket() SVG 繪圖函數。現行恒生指數仍由 TradingView 單一報價嵌入提供，沒有修改其原有流程。
G. 頁面顯示版本號更新為 v5.32，並新增測試報告及交接文件。

【3. 結構及功能一致性】
- HTML 21 個 Widget 的 class／id／順序與 v5.31 完全相同（已以 DOM parser 核對）。
- 全部原有 CSS 與 v5.31 逐字相同，沒有為本次審視刪除一大批可能仍有瀏覽器相容性用途的歷史規則。
- 圖片仍儲存在 localStorage `myday.photo.square.v1`；正方形置中剪裁與 Hover／觸控雙步操作不變。
- 提醒及重要日子本機資料鍵仍為 `myday.tasks`、`myday.daysMatter.v1`；相應的設定和日曆標記等鍵仍保持原位。
- 外部 HKO／Open-Meteo／九巴 API、TradingView 嵌入及 GitHub Actions 分頁與新聞工作流程不變。
- 專案尚未轉為模組化；GitHub Pages 仍以 `index.html` 作唯一主要前端入口。

【4. 審視發現：已修正】
[中] 靜態 news.json / 失效 RSS 快取的出站連結未做完整官方主機驗證；已在前端及 RSS Python 雙層加強。
[中／低] 損壞 localStorage JSON 的錯誤資料型別可能造成提醒／重要日子渲染中斷；已加保守型別檢查，不清除有效資料。
[低] 歷史 HSI 圖表函數沒有任何呼叫，增加維護負擔；已移除孤立函數（未更動現役 TradingView）。
[低] 空白提示模板重複維護、時間 Formatter 重建；已作等價整合。

【5. 仍有風險／未在本版強行改動】
[中] TradingView 會載入第三方 JavaScript；腳本無固定 SRI 雜湊，第三方服務供應鏈與瀏覽器追蹤政策需另行評估。立即移除／嚴格 CSP 可能令恒指 Widget 失效，本版保持原運作。
[中] 部分 localStorage store() 操作原有的 try/catch 會吞掉寫入失敗（容量或禁用），即時介面可能看起來已更新，但下次重開未必持久。圖片 Widget 已有獨立的儲存錯誤回報；其餘應在未來單獨設計資料備份／匯出與提示，再作實機驗證。
[中／低] GitHub Actions 使用版本標籤 actions/checkout@v4 等，而非固定 commit SHA，仍有供應鏈管理風險。改為固定 SHA 需另做持續更新與部署驗證。
[低] RSS 擷取流程在部分來源失敗而使用舊快取時，news.json 的全域 generated_at 仍可能反映本次同步時間而非該分類原始更新時間。修正應增設每分類時間欄位及前端顯示邏輯，屬功能更動，暫不在本輪加入。
[維護] 首頁約 335 KB，包含約 201 KB CSS、超過 1,200 個頂層 CSS 樣式規則及多個歷史覆蓋層。某些舊圖表 CSS 可能已不再引用，但一鍵清除的版面風險高。本次只移除可確認的死 JavaScript；未整理 CSS。建議未來以 Widget 為單位逐個抽取 CSS／JS，先對照 iPad Safari、iPad 橫直向及 Windows 畫面後再移除規則。
[驗證] 目前並無獨立滲透測試、真實 Safari 實機驗收或全部第三方 API 的正式網絡測試；「未見確定高危漏洞」不等同保證不存在漏洞。

【7. 安裝及回滾（保留原有資料）】
1. 先在 GitHub repository 保留 v5.31 的 commit／index.html 與 `scripts/fetch_news.py` 的備份。
2. 將 ZIP 內 `ipad-main/index.html` 覆蓋 GitHub Pages repository 根目錄 `index.html`。
3. 同步將 ZIP 內 `ipad-main/scripts/fetch_news.py` 覆蓋 repository 的 `scripts/fetch_news.py`。
4. 原有 `.github/workflows/pages.yml`、`data/news.json` 可保持不變；如以完整專案覆蓋，亦請確認保留原有 GitHub Actions Pages 設定。
5. Commit / Push 至部署分支（基準為 main），在 GitHub Actions 確認 Pages 部署成功。
6. 開啟網站用 `?v=532` 確認頁腳 v5.32，逐項檢查原有個人提醒、重要日子、已上傳圖片、分頁、天氣、新聞及九巴 ETA。
7. 如需回滾，將 `index.html` 和 `scripts/fetch_news.py` 同時復原至 v5.31 版本再部署。
8. **不要清除瀏覽器網站資料／localStorage**；個人提醒與圖片依附目前瀏覽器及網址來源，清除可能造成無法恢復的遺失。
